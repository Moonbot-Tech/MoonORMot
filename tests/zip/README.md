# ZIP regression

Direct `mormot.core.zip` qualification against independent Python ZIP fixtures.
It does not use `System.Zip` or Delphi implementation sources. Python 3.9+ and
the standard library are sufficient. Linux builds also require GCC's link libraries.

Run from any directory; all generated files stay under `--results`:

```text
python tests/zip/run.py --compiler PATH/ppcx64 --rtl PATH/units/x86_64-linux/rtl --mormot PATH/mormot --results OUTPUT --optimization O2
python tests/zip/run.py --compiler PATH/dcc64.exe --mormot PATH/mormot --results OUTPUT --optimization O2
```

MoonCompiler accepts `O-`, `O2`, and `O3`; its RTL directory is required. The test
uses the vanilla runtime, independently of the application's memory manager.
For Delphi Win64, `O-` disables optimization and `O2`/`O3` select Delphi `O+`.
The runner finds compiled Delphi RTL units relative to the compiler; `--rtl`
can override that directory. No proprietary RTL source path is added.

The 11 fixture variants cover seekable ZIPs, streaming ZIPs with signed and
unsigned data descriptors, local-only and full ZIP64 with small data,
offset-only ZIP64, comments, and unrelated extra fields. Each contains stored
and deflated entries, an empty entry, and several independently generated byte
payloads. Python validates each fixture before giving it to mORMot.

Each fixture runs 21 checks:

- `TZipRead` from memory, file, and file with `WorkingMem=512`; both `UnZip`
  overloads, `RetrieveFileInfo`, `TestAll`, and exact extracted bytes.
- `AddFromZip` from those three readers and from a ZIP appended to a prefix
  with `WorkingMem=512`. The small-memory read must actually use disk entries.
- `CreateFrom` append and no-op; removal of first, middle, last, and all entries,
  with both whole-file and small working memory.
- A filter exception after rejecting the first entry, before any move; the
  input ZIP must remain byte-for-byte unchanged.

Python checks every resulting ZIP with `testzip()`, then verifies the exact
ordered names and data. It does not require preservation of comments or extra
fields. A failing executable runs in an isolated process so the remaining
cases still report their outcomes. `cases/results.json` retains exit codes,
diagnostics, and per-case results; `build/` retains the compiler command/log.

An already-built executable can be checked separately:

```text
python tests/zip/verify.py --exe PATH/ZipRegression --results OUTPUT
```
